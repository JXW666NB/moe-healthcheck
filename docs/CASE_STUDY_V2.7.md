# 案例研究：TGAI NB V2.7

> 一个自训 3B 中文 MoE 的完整体检记录。
> 这个模型的结论是 **FAIL**，但它仍然能正确回答简单问题 ——
> 这正好说明「内部健康」与「输出质量」是两件事。

## 指标 ⑤：路由卡死 —— 用屏蔽实验验证

### 单专家禁用实验

| 配置 | 输出 | 卡死层数 | 层熵 | 确信度 |
|---|---|---|---|---|
| **基线（全开）** | `你好！很高兴认识你！😊` | **0 / 28** | **1.099** | 0.756 |
| 禁 E3 | `你是哪来的？` | 1 / 28 | 0.929 | 0.756 |
| 禁 E4 | `<TGAI><思考> 用户说你好…` | — | — | — |
| **禁 E6** | `您好！我是一个人工智能模型` | 1 / 28 | 1.002 | 0.768 |
| 禁 E5 | `您好！\n\n\n\n\n\n\n\n` （复读换行） | — | — | — |
| **禁 E7** | `你好！<UNK>\n\n我叫TG在吗？` | **2 / 28** | **0.832** | 0.760 |
| 禁 E1 | `\n(\nvt_\_0_n` | — | — | — |
| 禁 E2 | `**懒**********懒够****` | — | — | — |
| **禁 E0** | `我红我！精` | **13 / 28** | **0.414** | 0.692 |

### 两种失效模式

```
★ 模式 A：路由卡死（禁 E0）
  卡死 13/28，层熵 0.414（从 1.10 腰斩），确信度 0.692
  机制：隐藏态退化 → router 输入近似常量 → 固定选同一专家
  特征：输出极短（5 个字）、无意义、立刻 EOS

★ 模式 B：路由正常但专家错配（禁 E7）
  卡死 2/28，层熵 0.832（接近正常的 1.099），确信度 0.760（和基线一样）
  机制：路由照常灵活工作，但选中的专家不会干这活
  特征：前半句正常、后半句崩、出现 <UNK>
```

**★★★ 两种模式的输出都是「坏」，但原因完全不同。
只看输出无法区分；看卡死层数 + 层熵就能立刻判断。**

### C(8,2) = 28 对：**0 / 28 可用**

只保留两个专家、禁用其余六个，全部 28 种组合：

```
答案档：DEAD 7 / 垃圾或复读 21 / 真可用 0

```

### C(8,3) = 56 三对：**约 3~4 / 56 勉强可用**

```
答案档：GOOD 6（人工复核后真可用约 3）/ BAD 32 / DEAD 18
思考档：GOOD 10（真可用约 4）/ BAD 28 / DEAD 18

★ 全部 6 个"GOOD"里有 5 个含 E0
★ 思考档 10 个里有 9 个含 E0
```

### 结论：8 个专家零冗余

```
不是"某个专家是垃圾"，而是"容量刚好够用，砍谁都不行"
⇒ 没有可删的冗余专家
⇒ 这是架构/训练配方层面的问题，不是微调能救的
```

## 置换实验（验证「Super Expert 的超级在权重里」）

引擎支持 `tg_expert_remap_weight` / `tg_expert_remap_router`：

```
g_remap_w[slot] = src   → 槽位 slot 用专家 src 的权重
g_remap_r[slot] = src   → 槽位 slot 读专家 src 的 router 分数
```

### 结果

| 配置 | 输出 | 判定 |
|---|---|---|
| 基线 | `你好！很高兴认识你！😊` | — |
| **E0↔Ei 一致置换**（w + r 同步） | `你好！很高兴认识你！😊` | ✅ **逐字节相同** |
| **全排列一致置换**（反序/循环/随机） | `你好！很高兴认识你！😊` | ✅ **逐字节相同** |
| E0↔E1 只换权重 | 空（立刻 EOS） | ❌ |
| E0↔E1 只换路由 | 空（立刻 EOS） | ❌ |
| E0↔E4 只换权重 | `\n四！\n\n<UNK>\n**<UNK>` | ❌ |
| E1↔E3 只换权重 | `我问你面前的问题，为什么我"` | ✅ 通顺 |
| E4↔E5 只换权重 | `你好！\n\n我想跟你聊聊天机器` | ✅ 通顺 |
| E6↔E7 只换权重 | `\n这个问题是否可以理？` | ✅ 通顺 |

### 三个结论

```
① 一致置换 100% 逐字节相同（15/15 组）
   ⇒ 重映射实现正确，MoE 的专家编号是「等价类」，本身无意义

② 「只换权重」和「只换路由」的输出完全相同
   数学原因：对自逆置换 π，
     Σ softmax(r)[k]·W[π(k)] 与 Σ softmax(r)[π(k)]·W[k]
   重排后求和等价

③ 动了 E0 就崩；E4/E5/E6/E7 之间互换基本无损
   ⇒ Super Expert 的「超级」属性存在于【权重本身】
   ⇒ 不是 router 的指派，也不是槽位编号
```

## 这个案例的总结

### 有硬证据的

```
① 残差范数 ×595~662，与提示词长度无关 ⇒ 内部表示不健康
② 22/28 层头号关注是 <BOS>，最深可达 w=1.000 ⇒ head 容量被浪费
③ 专家权重两簇（320 vs 180），差异只存在于 L1-L19；
   深层 L20-L27 完全趋同 ⇒ 深层不分专家、不看内容
④ C(8,2)=0/28、C(8,3)=3~4/56 ⇒ 8 个专家零冗余
⑤ 一致置换逐字节相同，只换权重即崩 ⇒ Super Expert 的超级在权重里
⑥ 两种失效模式：路由卡死（禁 E0）/ 专家错配（禁 E7）
```

### 不能确认的

```
① 是「训练配方」还是「架构设计」导致上述现象
   · 残差爆炸：学习率/初始化（训练）或 缺 residual scaling（架构）
   · 深层 sink 化：训练步数不足 或 28 层对小模型偏深
   ⇒ 需要训练配置 + 对照 checkpoint

② 这些指标与「输出质量」的相关性
   · 模型仍能正确回答简单问题
   · 准确表述是「能活但长不高」
```

### 算力利用率视角

```
预算是 28 层 × 8 专家
实际承担语义工作的：约 L0~L20（21 层，75%）
后 7 层（25%）在推理时基本空转
8 个专家全部必需，无冗余 ⇒ 容量已用满甚至不够

⇒ 若能把 28 层全部用起来，同等参数量下有效深度 +33%
```

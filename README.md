# moe-healthcheck

> **MoE 模型的五项无监督体检** —— 不需要标注数据，不需要评测集，
> 只跑一次前向 + 读一遍权重，30 秒内知道这个模型「内部是否健康」。

**一个诊断工具，不是一篇论文。** 它把已知的 MoE 失效模式固化成可自动化的检查项，
方便在训练中途随时发现「模型在硬撑」的状态。

---

## 它测什么

| # | 指标 | 健康参考 | 说明 |
|---|---|---|---|
| ① | **残差流范数增长** | 2 ~ 10× | 峰值 / 首层。>30 报警，>100 判失败 |
| ② | **注意力集中度** | 单 head 最大权重 ≤ 0.9 | `=1.0` 表示该 head 完全退化为常数 |
| ③ | **内容 head 分布** | 深层 ≥ 浅层的一半 | 「内容 head」= Top-1 不是模板标记/换行，且熵 ≤ 0.5 |
| ④ | **专家权重分布** | CV ≤ 0.15 | 两簇分离 ⇒ 容量分配不均 |
| ⑤ | **路由卡死层数** | ≤ 3 层 | ≥10 层 ⇒ 隐藏态已退化为近似常量 |

### 第 ⑤ 项是本工具的重点

```
router 的输入 = ln2(h)，即"当前 token 在这一层的隐藏态"
                ↓
隐藏态健康 → 不同 token 的 ln2(h) 差异明显 → 每步换专家 → 卡死层数 ≈ 0
隐藏态退化 → ln2(h) 近似常量          → 固定选同一专家 → 卡死层数 ↑
```

**★★ 所以「连续 N 步里始终选同一专家的层数」是隐藏态健康度的零成本代理指标。**
**不需要人工判读输出，纯数值、可自动化、可直接接进训练监控。**

## 快速开始

```bash
# 1. 装依赖
pip install numpy
pip install -e "path/to/tgai_go"     # TGAI 引擎 Python 绑定

# 2. 跑体检
python moe_health.py path/to/model.tg

# 3. 只看某一项
python moe_health.py model.tg --only routing

# 4. 写 JSON（便于训练中途对比）
python moe_health.py model.tg --json report.json
```

**★ 引擎要求**：`libtgai_engine.dll` 需支持
`tg_dump_set_enabled` / `tg_expert_set_disabled`（2026-10-18 之后的版本）。

## 一个手动验证：故意弄坏它

用引擎的专家屏蔽功能，观察指标如何变化（需要在 Python 里直接调）：

```python
from tgai_go import _engine
eng = _engine.TGEngine()
eng.load('model.tg')

# 禁用一个必需专家
eng.lib.tg_expert_set_disabled(0, 1)
# → 复测：路由卡死从 0 层变成 13 层，层熵从 1.10 掉到 0.41
```

**★ 实测对照（TGAI NB V2.7，28 层，8 专家）：**

| 配置 | 输出 | 卡死层数 | 层熵 | 确信度 |
|---|---|---|---|---|
| 基线 | `你好！很高兴认识你！` | **0 / 28** | 1.099 | 0.756 |
| 禁 E6 | `您好！我是一个人工智能模型` | 1 / 28 | 1.002 | 0.768 |
| 禁 E7 | `你好！<UNK>...` | 2 / 28 | 0.832 | 0.760 |
| 禁 E0 | `我红我！精` | **13 / 28** | **0.414** | 0.692 |

**★★ 出现了两种不同的失效模式：**

```
模式 A（禁 E0）：路由卡死
  隐藏态退化 → router 输入近似常量 → 13 层固定选同一专家
  输出极短、无意义、立刻结束

模式 B（禁 E7）：路由正常但专家错配
  路由还很灵活（卡死 2 层，熵 0.83），确信度也和基线一样
  但被选中的专家不会干这活 → 前半句正常、后半句崩
```

**★★★ 这两种模式的区分，只能靠「卡死层数 + 层熵」这种数值指标，
肉眼看输出是不够的。**

## 适用范围与局限

**✅ 适用**

- 自训 MoE 模型（`.tg` 格式，TGAI 引擎）
- 训练中途的 checkpoint 对比（同一套阈值）
- 诊断「输出还能用但内部已退化」的隐性故障

**❌ 不适用 / 需注意**

- **不衡量输出质量**。残差 ×600 的模型仍可能把简单问题答对
- **需要一次真实前向**，不能只读权重（除指标 ④）
- **阈值是在 3B / 28 层 / 8 专家上校准的**，其他规模需要重新标定
- **单模型、单提示词的结论不能外推** —— 见 [docs/LIMITATIONS.md](docs/LIMITATIONS.md)

## 相关工作

本工具的五项指标，前四项分别对应以下已发表工作：

| 指标 | 相关工作 |
|---|---|
| ①②③ | [Unveiling Super Experts in MoE LLMs](https://proceedings.iclr.cc/paper_files/paper/2026/hash/c01b90b643d0e877cff0f34cbe27410f-Abstract-Conference.html)（ICLR 2026）—— massive activation 与 attention sink 塌陷是同一机制 |
| ④ | [Router Sensitivity Under Lightweight Fine-Tuning Identifies Prunable Experts](https://arxiv.org/abs/2608.07890) —— router 敏感度可识别可剪专家 |
| ⑤ | [Diagnosing and Stabilising Routing Behaviour in MoE Models](https://zenodo.org/records/19770276) —— 路由行为诊断 |

**★★ 本工具的价值不在于提出新理论，而在于：**

1. **把上述结论固化成一个 5 分钟能跑完、有统一阈值的检查脚本**
2. **提出「卡死层数」作为隐藏态健康度的可直接监控的数值**
3. **给出两种失效模式（卡死 vs 错配）的判别方法**

**如果你的模型不是 `.tg` 格式，前四项指标的方法仍然适用，
只需要把 dump 换成自己框架的 hook。指标定义见 [docs/METRICS.md](docs/METRICS.md)。**
